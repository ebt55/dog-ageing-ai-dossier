# Can MAMMAL do dogs? Species coverage, transfer analysis, and a canine fine-tuning plan

> Part of the dog-ageing research dossier · Written 2026-10-04 by Opus 5.5 subagent · Status: independently verified by Fable 5.1 on 2026-10-04 — see ../07_verification/mammal_verification.md · Licence: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

## TL;DR

- **Nothing in MAMMAL is dog-specific, and one whole modality is human-only by construction.** The CELLxGENE pretraining set was built "after filtering for **human** samples" [1, Suppl. §3.3] ✅, and the gene vocabulary is **human gene symbols plus 2,049 human Ensembl `ENSG…` IDs, with zero dog `ENSCAFG…` identifiers** [3] ✅.
- **The antibody side is the worst case.** All 1,300 M antibody pretraining samples come from OAS, whose species list is **human, mouse (4 strains + 2 engineered), rat, rabbit, rhesus, bactrian camel** — **no dog** [4] ✅. The model's six organism tokens (`HUMAN, MOUSE, RAT, RABBIT, MONKEY, CAMEL`) map one-to-one onto that list [3] ✅, so MAMMAL has **no token and no training signal for canine immunoglobulin germlines**. This directly limits its usefulness for caninized therapeutic antibodies such as lokivetmab or bedinvetmab.
- **The chemistry side transfers for free.** ZINC22 + PubChem SMILES are species-agnostic; so are the SMILES tokenizer and the small-molecule tasks' *inputs*. But the *labels* (BBBP, ClinTox, IC50) are human-derived, and canine ADME differs — most sharply at the blood–brain barrier, where the collie/herding-breed **ABCB1(MDR1) 4-bp deletion** truncates P-glycoprotein and makes canine BBB penetration breed-dependent [5] ✅.
- **The protein side partially transfers.** UniRef90 has no stated species filter, and dog proteins are present but vanishingly rare: **19,003 UniRef90 clusters contain a dog member**, against the 180 M clusters MAMMAL sampled (~0.01 %) [6] ✅. STRING v12.5 *does* include dog (verified: dog TP53 → `9615.ENSCAFP00000064590`) and the paper describes negatives as "randomly matching proteins **from the same species**", implying a multi-species STRING pull [1, Suppl. §3.3; 7] 🟡 — so canine PPI pairs were plausibly seen.
- **Hard number for the transcriptomics question:** I intersected STRING v12.0's canine protein list with MAMMAL's gene vocabulary. **15,784 of 20,199 canine gene symbols (78.1 %) have an exact-match token; 19,352 of 19,699 human symbols (98.2 %) do** [3, 7] ✅ **— independently re-computed and reproduced to the digit** [verifier-confirmed]. Of the 4,415 misses, **about 44 % are genes with no real symbol at all** (`LOC…` identifiers 1,120; UniProt-accession placeholders such as `E2R118_CANLF` 803; plus bare `ENSCAFP…` ids), ~5 % are canine comparative-nomenclature names (`C10H12orf56`-style, 209), ~3 % are chemosensory receptors and ~3 % are `-2`/`-3` paralog suffixes — leaving **~45 % that are properly named canine symbols**, including canine-specific families and genes under non-current nomenclature [verifier-corrected: the draft said the misses were "overwhelmingly un-named genes" and fell into "four recognisable buckets", which together cover only about half]. So a dog expression profile is **~78 % tokenizable by symbol matching alone**, before any ortholog mapping.
- **Three things work essentially as-is** (small-molecule property prediction, protein–protein interaction / ΔΔG on canine sequences, DTI against canine target sequences); **three need fine-tuning on canine data** (cancer-drug response, cell-type annotation, antibody–antigen binding); **two are blocked or near-useless** (canine antibody *design*, and anything requiring DNA — MAMMAL has **no nucleotide modality at all** [1, 3] ✅).
- Canine data to fine-tune on **does exist**, and I verified it: the **Flint Animal Cancer Center canine tumour cell line panel** with phenotype+genotype data [8], **990 dog cell lines in Cellosaurus** [9], a **canine leukocyte scRNA-seq atlas** (7 healthy + 10 osteosarcoma dogs, 36 populations) [10], a **canine peripheral-blood TCRαβ T-cell atlas** [11], and the **Dog Aging Project** [12, 13]. Useful coincidence: GDSC already screens rapamycin, temsirolimus, AZD8055, navitoclax, dasatinib and venetoclax [14] ✅ — the mTOR/senolytic compounds the dog-ageing field cares about are inside the human training distribution.

## 2. What the tokenizer can and cannot say about a dog

All findings in this section come from the shipped tokenizer files in the Hugging Face repo [3] ✅.

**Organism tokens — six species, and none is canine.** The `AA` sub-tokenizer's vocabulary has 340 entries, 314 of them `<…>` special tokens, and the organism-related ones are exactly:
`<ORGANISM>`, `<ATTRIBUTE_ORGANISM>`, `<ATTRIBUTE_ORGANISM_HUMAN>`, `<ATTRIBUTE_ORGANISM_MOUSE>`, `<ATTRIBUTE_ORGANISM_RAT>`, `<ATTRIBUTE_ORGANISM_RABBIT>`, `<ATTRIBUTE_ORGANISM_MONKEY>`, `<ATTRIBUTE_ORGANISM_CAMEL>`
— **eight tokens, of which six name a species** [verifier-corrected: the draft omitted the bare `<ORGANISM>` token]. The identical set appears in **all four** sub-tokenizer files, including the SMILES BPE file (shared special-token space) [verifier-corrected from "all three"]. The six species are **exactly OAS's species list** (rhesus → MONKEY, bactrian camel → CAMEL), confirming the organism vocabulary was derived from the antibody corpus. A canine sequence must therefore be submitted either untagged or with the bare `<ATTRIBUTE_ORGANISM>` / `<ORGANISM>` token. ✅
*Mitigation:* the paper states the tokenizer is extensible — "New tags can be introduced into individual sub-tokenizers or added to the shared token set without disrupting existing functionality… updates to domain-specific sub-tokenizers or the token vocabulary maintain backward compatibility" [1, Methods 4.3] ✅. Adding `<ATTRIBUTE_ORGANISM_DOG>` is cheap; giving it meaning requires canine training data.

**Gene vocabulary — human nomenclature.** 95,218 tokens, 94,904 of them bracketed gene entries. Spot checks: `[TP53]`, `[GAPDH]`, `[MALAT1]`, `[XIST]`, `[CDKN2A]`, `[IGF1]`, `[GH1]`, `[TERT]`, `[MTOR]` **present**; the mouse-convention forms `[Trp53]`, `[Gapdh]` **absent**. 2,049 tokens embed human `ENSG…` accessions; **zero** embed dog `ENSCAFG…` accessions. ✅

**Measured canine coverage.** Intersecting STRING v12.0's `9615.protein.info` preferred names with the vocabulary [3, 7] ✅:

| Species | Protein-coding entries in STRING | Symbols with an exact token | Coverage |
|---|---|---|---|
| *Canis lupus familiaris* | 20,199 | 15,784 | **78.1 %** |
| *Homo sapiens* | 19,699 | 19,352 | **98.2 %** |

All seven example symbols below were confirmed present in the STRING dog list and absent from the tokenizer [verifier-confirmed]. The 4,415 canine misses break down as follows — measured, not estimated [verifier-corrected: the draft's four buckets account for only ~52 % of the misses]:

| Bucket | Count | Share | Examples |
|---|---|---|---|
| NCBI `LOC…` identifiers (no symbol) | 1,120 | 25.4 % | `LOC610160`, `LOC100683099` |
| UniProt-accession placeholders (no symbol) | 803 | 18.2 % | `E2R118_CANLF`, `F1PA32_CANLF` |
| Canine comparative-nomenclature names | 209 | 4.7 % | `C10H12orf56`, `C12H6orf15`, `CXHXorf38` |
| Chemosensory receptors (olfactory / vomeronasal / taste) | 149 | 3.4 % | `cOR1X2`, `COR11G5`, `CFOLF1`, `CANFAMV1R558`, `CAFA-T2R12` |
| `-2`/`-3` paralog suffixes | 135 | 3.1 % | `AHNAK-2`, `AK3-2` |
| **Other properly named canine symbols** | **1,999** | **45.3 %** | see below |
| **Total** | **4,415** | 100 % | |

The large "other" bucket is the finding the draft missed, and it matters more than the placeholders [verifier-added]. It contains **canine-specific gene families** — the β-defensins (`CBD103`, `CBD104`, `CBD107`, `CBD108`, `CBD130`, `CBD131`, `CBD138`, `CBD140`; `CBD103` is the K-locus black-coat gene), **the canine MHC** (`DLA-DRA`, `DLA-DQA1`, `DLA-DMA`, `DLA-DOA`, `DLA88`), and **canine drug-metabolising cytochromes** (`CYP2D15`, `CYP3A12` — the dog orthologues of human CYP2D6 and CYP3A4) — plus genes under superseded nomenclature (`ATP5MD`, `ATP5MPL`, `CCDC56`) and canine-expanded families (`APOBEC3Z1/Z3`, `AOX2/AOX4`). Three practical implications: (a) **a dog expression matrix is ~78 % usable by naive symbol matching**; (b) the missing 22 % is systematically biased toward poorly annotated and canine-specific genes, so a naive pipeline silently drops exactly the dog-specific biology; (c) **the specific losses include canine immunogenetics (DLA) and canine pharmacogenetics (CYP2D15/CYP3A12)** — the two gene sets most relevant to §4.2's immunogenicity risk and §3's drug-metabolism caveat respectively. Any canine pipeline should hand-map these before anything else.

**Ortholog mapping is not a solved sub-problem.** Ensembl REST homology returns a clean one-to-one for some ageing genes and nothing for others: human **IGF1** → dog `ENSCAFG00845009366`, `ortholog_one2one`, 87.6 % / 68.7 % identity ✅; human **CDKN2A** → **no homologies returned** in the current release ✅ — and CDKN2A/p16 is a canonical senescence marker. Dog reference genebuild is `ROS_Cfam_1.0` (GCA_014441545.1, 2.40 Gb, genebuild 2020-10) [16] ✅. Anyone building the mapping table must handle one-to-many orthologs, missing orthologs, and the three other dog assemblies in UniProt (UP000002254 CanFam3.1-era, UP000694429, UP000694542) [6].

**Label vocabularies are species-neutral — a genuine advantage.** The `CELL_ATTRIBUTES` sub-tokenizer holds **580 `[CL:…]` Cell Ontology terms and 209 `[UBERON:…]` anatomy terms** [3] ✅. Both ontologies are cross-species, so `[CL:0000084]` (T cell) or `[UBERON:0002113]` (kidney) are valid labels for a dog. The *output* space of the cell-type task needs no modification; only the *input* representation and the learned mapping do.

**No DNA.** There is no nucleotide sub-tokenizer and no DNA sequence entity token. Canine germline variants (breed GWAS hits, the MDR1 deletion, IGF1 haplotypes) **cannot be given to MAMMAL as sequence**. They can only enter indirectly, as their downstream expression consequences. ✅

## 3. Task-by-task transfer assessment

| MAMMAL capability | Canine readiness | Why |
|---|---|---|
| **Small-molecule property prediction** (BBBP, ClinTox, carcinogenicity, solubility) | 🟢 **Works as-is for input; labels need care** | Input is SMILES only — species-free. But every label is human-derived. BBBP is the trap: canine P-gp function varies by breed because of the ABCB1(MDR1) 4-bp deletion, which "results in a frame shift, generating several stop codons that prematurely terminate P-gp synthesis" and causes ivermectin neurotoxicity in collies [5] ✅. A "crosses the BBB" prediction from a human-labelled model is not breed-valid in dogs. ClinTox's FDA-approval sub-task is meaningless for veterinary products (approved by USDA/CVM or EMA under different frameworks [17, 18]) |
| **DTI / binding affinity** (protein sequence + SMILES → pKd) | 🟢 **Usable zero-shot with canine target sequences** | Input is just the target's amino-acid sequence; swap the human ortholog for the canine one from UniProt. Physico-chemical binding is reasonably conserved; expect degradation where the binding site differs. No fine-tuning strictly required, though canine-specific calibration would help |
| **PPI classification / generation; ΔΔG regression** | 🟢 **Usable zero-shot** | Sequence-only; STRING pretraining plausibly included dog [7] 🟡. SKEMPI-trained ΔΔG transfers at the level of general protein biophysics |
| **Cancer-drug response (IC50)** | 🟡 **Needs canine fine-tuning** | Two inputs: drug SMILES ✅ and a **ranked human gene list** ✗. Requires (a) canine→human symbol/ortholog mapping (78 % direct hit, §2) and (b) re-fitting on canine IC50 data, because canine tumour biology and drug metabolism differ. Nothing structural blocks it |
| **Cell-type annotation from scRNA-seq** | 🟡 **Needs canine fine-tuning, but the label space is already right** | Input needs ortholog mapping; the CL-ontology output space is species-neutral [3] ✅. The dominant risk is distribution shift in the *ranking* — gene-rank statistics in dog PBMCs differ from human PBMCs, and MAMMAL learned ranks on 30 M human cells only |
| **Antibody–antigen binding classification** | 🟡 **Needs canine fine-tuning, with a weak starting point** | Recall that *pre-trained* MAMMAL is at chance even on human targets (AUROC 0.530 HER2; 0.406–0.663 on nanobody targets) [1, Suppl. S5–S6] ✅ — all of the performance came from supervised fine-tuning. For dogs you would be fine-tuning from an antibody representation that never saw a canine antibody |
| **Antibody CDR design (infilling)** | 🔴 **Effectively blocked for canine frameworks** | The generative prior over CDR sequence is learned from 650 M OAS sequences with **no dog** [4] ✅ and conditioned on `<ATTRIBUTE_ORGANISM_HUMAN>`-style tokens that have no canine counterpart [3] ✅. Infilling a canine framework would sample human-like CDRs — plausible chemistry, wrong germline context, and immunogenicity risk in the dog. Needs a canine antibody repertoire corpus first (see §4.2) |
| **Anything genomic** (variant effect, breed genetics, methylation clocks) | 🔴 **Out of scope entirely** | No nucleotide modality [1, 3] ✅. Use a DNA foundation model instead; MAMMAL is the wrong tool |
| **Wolf-specific anything** | 🔴 **No data** | UniProtKB holds **199** *Canis lupus* (9612) entries [6] ✅. Wolves must be handled through dog orthologs plus the ~0.2 % dog–wolf coding divergence; there is no wolf transcriptomic, antibody or cell-line resource comparable to the canine ones in §4 ❓ |

## 4. Concrete fine-tuning plan for canine ageing use cases

### 4.1 Canine cancer drug response

**Why it is the best first target.** It is MAMMAL's most mature multi-modal task (two of eleven benchmarks, plus a shipped example and config: `mammal/examples/cell_line_drug_response` with GDSC1/GDSC2 switchable via `dataset_name`, accepting either a GDSC cell-line name or a custom `.h5ad` plus a drug SMILES [19] ✅). Canine cancer is also where comparative oncology is strongest — dogs develop spontaneous osteosarcoma, lymphoma, hemangiosarcoma and mast-cell tumours, and the canine lifespan compresses the natural history.

**Do canine cancer cell-line screens exist?** Yes, though nothing at GDSC scale ✅:
- **Flint Animal Cancer Center (FACC) Canine Tumour Cell Line Panel** — explicitly built as the canine analogue of NCI60/GDSC: "Current cell line panels with large amounts of associated drug sensitivity and genomics data are comprised of human cancer cell lines (i.e. NCI60 and GDSC)… We have assembled a panel of canine cancer cell lines… and report here phenotypic and genotypic data associated with these cells" [8] ✅. **This is the single most important resource for this use case.**
- **Cellosaurus lists 990 cell lines with `NCBI_TaxID=9615`** [9] ✅ — a catalogue to mine for provenance, tissue of origin and breed (entries carry a `Breed/subspecies` field, e.g. `Beagle; VBO=VBO_0200131`).
- Scattered single-lab drug-sensitivity studies: canine histiocytic sarcoma lines with 16 drug-resistance genes [20], canine hemangiosarcoma doxorubicin resistance [21], canine mammary tumour lines [22], canine lymphoid tumour ABCB1 epigenetics [23]. Small n, heterogeneous assays — usable for validation, not for training.

**Plan.**
1. Build the gene mapping once: canine symbols → MAMMAL gene tokens by exact match (78.1 % hit), then Ensembl `homology/symbol/dog/<gene>?target_species=human;type=orthologues` for the remainder, keeping one-to-one orthologs and logging one-to-many and missing cases (CDKN2A is a known miss — handle explicitly). Freeze and version this table; it is the main source of silent error.
2. Reproduce the human baseline first: fine-tune on GDSC2 via the shipped example and confirm Pearson ≈ 0.93 [1, Table 1]. If you cannot reproduce it, stop — nothing downstream is interpretable.
3. Three-way evaluation on canine data: (a) **zero-shot** transfer of the GDSC-trained model to FACC canine profiles, (b) **fine-tuned** on canine IC50s, (c) **jointly trained** on human + canine with a species attribute token added to the tokenizer (the paper guarantees backward-compatible extension [1, Methods 4.3]). The human→dog zero-shot number is itself a publishable result about cross-species transfer of drug-response models.
4. Prioritise compounds that are both in GDSC (so the model has seen them) and ageing-relevant. Re-verified present in GDSC release 8.5, with targets as listed [14] ✅ [verifier-confirmed, every DRUG_ID exact]: **Rapamycin/Sirolimus** (DRUG_ID 3, 1084; MTORC1), **Temsirolimus** (1016; MTOR), **AZD8055** (1059; MTORC1+MTORC2), **Navitoclax/ABT-263** (1011; BCL2/BCL-XL/BCL-W), **Venetoclax** (1909; BCL2), **Dasatinib** (51, 1079; ABL/SRC/…). The senolytic (navitoclax, dasatinib) and mTOR (rapamycin, temsirolimus, AZD8055) axes are therefore inside the training distribution — which matters because rapamycin is the compound the dog-ageing field has actually taken into companion-dog trials. The catalogue holds **621 compounds in total**, so presence in GDSC is not a given: check each candidate, and check development code names too — nintedanib, for instance, is listed only as `BIBF-1120` [verifier-added; see `mammal_paper_deep_dive.md` §6].
5. Caveats to write into any report: IC50 in an immortalised cell line is not efficacy in a dog; canine hepatic metabolism and P-gp differ; and the model sees expression only (no mutations/CNV), as in the paper [1, §2.4].

### 4.2 Caninized therapeutic antibodies

**The commercial reality.** Three veterinary monoclonals are approved and all three are species-engineered ✅:

| Product | INN | Target | Species | Approvals |
|---|---|---|---|---|
| **Cytopoint** | **lokivetmab** | **IL-31** | caninized | USDA **Dec 2016**; EMA **2017** — "the first monoclonal antibody to be approved for use in animals in the European Union"; dosed subcutaneously, effective 4–8 weeks [17] |
| **Librela** | **bedinvetmab** | **NGF** | **fully canine** | EU **Nov 2020**; US **May 2023** — "the first monoclonal antibody approved in the United States for controlling osteoarthritis pain in dogs"; >18 million doses distributed by an April 2025 pharmacovigilance report [18] |
| **Solensia** | **frunevetmab** | **NGF** | **cat**-specific | EU **Feb 2021**; US **Jan 2022** — "the first monoclonal antibody drug approved by the US Food and Drug Administration for animal use" [24] |

Two of the three target **NGF for osteoarthritis pain** — i.e. the existing veterinary antibody market *is* substantially an ageing-related market, which makes this directly relevant to the dossier.

**The blocker, stated plainly.** MAMMAL's antibody prior is human/mouse/rat/rabbit/rhesus/camel [4] ✅. Using it to design or screen caninized CDRs means asking a model with no canine germline knowledge to respect canine framework context. The right sequence of work is:

1. **Build a canine antibody corpus first.** This is the prerequisite and it does not exist in OAS. Candidate routes: canine BCR-repertoire sequencing studies (the field is small — a Europe PMC title-level search surfaced veterinary phage-display library work [25] and BCR sequencing in other non-model species such as ferret [26], but no canine OAS-scale resource) ❓; IMGT canine IGHV/IGKV/IGLV germline sets 🟡 (not verified here); and the sequences of the approved products themselves (patent/regulatory filings) 🟡.
2. **Add `<ATTRIBUTE_ORGANISM_DOG>`** to the shared special-token set and continue pretraining the antibody LM + denoise tasks on that corpus. The architecture explicitly supports this [1, Methods 4.3] ✅.
3. **Then** attempt the useful tasks: (a) classify canine-antibody/canine-antigen binding (feasible with modest labelled data, as the human HER2 fine-tune shows — but note the human fine-tune used 8,935 binders + 25,114 non-binders [1, §2.9], a scale no canine programme has); (b) caninization itself — graft CDRs from a mouse or human antibody onto a canine framework and use the infilling head to propose framework-compatible CDR variants. (b) is the genuinely attractive application, because it is exactly the CDR-infilling task MAMMAL is best at, just with a different framework distribution.
4. **Immunogenicity is the risk that matters.** A human-prior model will propose human-like CDRs; in a dog those are a potential anti-drug-antibody liability. Any generated sequence needs canine germline-similarity screening before it is taken seriously.

Interim honest answer: **MAMMAL today cannot design canine antibodies, and fine-tuning it for that requires building a dataset the field has not yet built.**

### 4.3 Dog single-cell data and cell-type annotation

**Resources verified** ✅:
- **Canine leukocyte atlas** — Ammons et al., *Front. Immunol.* 2023: scRNA-seq of circulating leukocytes from **7 healthy and 10 osteosarcoma-affected dogs**, identifying "**36 unique cell populations**… with a remarkable amount of heterogeneity in CD4 T cell subtypes", plus MDSC expansion in tumour-bearing dogs [10]. Explicitly motivated by canine reagent limitations — the same problem MAMMAL could reduce.
- **Canine peripheral blood TCRαβ T-cell atlas** — Eschke et al., *Front. Immunol.* 2023: single-cell transcriptome **plus V(D)J repertoire** sequencing of healthy dogs, yielding **22 TCRαβ⁺ clusters** (11 CD4-dominant, 8 CD8A-dominant, 3 mixed) and "first evidence for the existence of canine mucosa-associated invariant T cell (MAIT)-like cells" [11] ✅ [verifier-expanded]. Doubly relevant: the paired V(D)J data feed both the cell-type task **and** MAMMAL's TCR-epitope binding task.
- Disease-specific canine scRNA-seq exists but is scattered: pro-fibrotic macrophages in canine idiopathic pulmonary fibrosis (West Highland White Terriers) [27], intratumoral heterogeneity of canine osteosarcoma lines [28], canine MDSC characterisation [29].
- **No canine data in CZ CELLxGENE Census** (human, mouse, macaque, marmoset, chimp only as of the 2025-11-08 LTS release) [15] ✅ — so there is no "just pull it from Census" path.

**Plan.** The shipped `scrna_cell_type` example already specifies the exact input contract and gives a reference preprocessing script [19] ✅: AnnData `.h5ad`, cells × genes, `.X` must contain **only** gene counts, labels in `.obs['cell_type']`, preprocessing = drop cells with < 200 distinct genes → normalise total counts to 1.0 → `log(x+1)` → **uniform binning into n bins where a lower bin number means a higher count**, written back into `.X`. Crucially the README warns: "**all the names of genes and cell types need to be consistent with the format/naming schema in the tokenizer**" [19] ✅ — i.e. the canine→human symbol mapping of §2 is not optional, it is the documented requirement. Steps: map symbols (78 % direct), relabel canine cell types to CL IDs already in the `CELL_ATTRIBUTES` vocabulary, reproduce Zheng68k first as a sanity check (F1 ≈ 0.763), then (a) zero-shot the human-trained model on dog PBMCs to measure cross-species transfer, and (b) fine-tune on the canine atlases. A clean zero-shot-vs-fine-tuned comparison on dog PBMCs would be a small, publishable, genuinely useful result — and the honest answer might be that transfer is poor, which is equally worth knowing.

### 4.4 Dog Aging Project data

**What it is** [12] ✅: "a long-term longitudinal study of ageing in **tens of thousands** of companion dogs", collecting "extensive survey data, environmental information, electronic veterinary medical records, genome-wide sequence information, clinicopathology and molecular phenotypes derived from blood cells, plasma and faecal samples", designed as an **open-data, community-science** resource. Rationale directly relevant to this dossier: dogs "share the human environment and have a sophisticated healthcare system but are much shorter-lived than people". Earlier framing paper: Kaeberlein et al., *Mamm. Genome* 2016, "translational geroscience in companion animals" [13] ✅. Downstream analyses already published include dog size vs disease history across the age spectrum [30], lifetime tumour prevalence from the baseline survey [31], and physical-activity/cognitive-dysfunction associations [32].

**Fit with MAMMAL — mostly poor, and worth saying so.** DAP's richest layers are **survey, EHR and genome-wide sequence** data. MAMMAL consumes none of those: no free text (an explicit non-feature [1, Methods 4.1]), no DNA, no tabular covariates. The only DAP layers MAMMAL could ingest are (a) **molecular phenotypes from blood cells** if any are transcriptomic (then §4.3 applies), and (b) **clinicopathology scalars**, which MAMMAL can at least represent natively via its scalar projection — but there is no pretrained task that maps blood chemistry panels to anything. I was unable to load the DAP open-data access page (it renders client-side) so I cannot state which data types are currently released, under what agreement, or on which platform ❓ — that needs a browser session, and the dog-ageing-biology subagent is better placed to document it.

**Honest recommendation:** do **not** position MAMMAL as a Dog Aging Project analysis tool. Position it where its modalities actually line up: canine **cancer pharmacology** (§4.1) and canine **antibody engineering** (§4.2, after corpus-building). Use DAP for the epidemiology and the phenotype definitions that tell you *which* interventions are worth modelling.

## 5. If we only did one thing

Build the **canine gene-symbol → MAMMAL-token mapping table** (measured 78.1 % direct hit, Ensembl orthology for the rest) and run the **zero-shot human→dog transfer test on cancer-drug response** using the FACC panel. It is cheap (one 458 M-parameter model, single GPU [2]), it uses a shipped example config [19], it reuses a resource that already exists [8], and whichever way it comes out it produces a number nobody currently has: *how well does a human-trained multi-modal drug-response model transfer to dogs?* Everything else in this file depends on knowing that number.
